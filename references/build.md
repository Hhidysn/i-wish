# 产出与验证

## 产出

- 先看实际文件，保留别人的改动。
- 按已批准的增量做。开发者自测只算补充。
- 每张任务闭环：记录起始 revision 或产物状态 → 派有界简报 → 收报告和变更范围 → 独立审查 → 修 → 只复审受影响部分。
- 复审有上限。到上限就升级、换人，或主代理裁决，别把阻塞项搁着。
- 失败先诊断：没有新证据就别反复试。复现、缩小范围、一次验一个假设。修根因后重查回归和原场景，再决定升级还是重设计。
- 别降标准：不降阈值、不删检查、不跳过检查、不加空实现。
- 阻塞验收的缺陷都在范围内，跟哪来的无关。其他改进另开任务。

正式版：模块首次开工，或证据、设计失效时，走一遍 差异 → 补证据 → 细化 → 独立审查 → 放行。普通任务引用现行设计，不重开采访。契约变了就让受影响的任务和证据失效，相关的都等更新后再动。

## 独立验证

编码执行、角色作业与证据格式见 execution-standards 技能（references/orchestrator.md、references/verifier.md）；需求、设计门禁和完成判断仍按 i-wish。

- 产物形成后，派一个没参与产出的新作者写验收。角色边界见 [agents.md](agents.md)。
- 初始只给已批准的行为和验收、公开接口、失败规则、测试设施和数据、能跑的入口；不给实现、产出者的推理、自测结论和建议的断言。
- 先按需求冻结正常、边界、错误、状态与恢复、集成用例，再看实现。
- 用例落到现有设施上：能测就写测试；静态、视觉、文档、配置产物用渲染、交互或通读检查。
- 证据门槛：写了测试没跑、只跑 mock、只做 dry run，都不算证明真实行为。最终验证要用真实生产者和真实依赖，只对声明的范围负责；已批准的 stub 能支撑开发，不能当作最终验收。
- 记录格式：`Run:` 做了什么，`Expected:` 应该看到什么，`Observed:` 实际看到什么。没完成观察的声明不算证据。
- 只读作者返回精确补丁，主代理机械应用并运行，分别记下作者、应用者和执行者。语义、预期或数据要改，退回作者；产品缺陷交写入方。
- 分歧按已批准行为裁决，记下理由。

独立审查：锁定候选版本和变更范围，包含相关的未跟踪改动。需求和规范分别给结论，一边通过不能抵消另一边失败。正式版用不同上下文审；轻量版可以在行为用例冻结后，由一名独立审查者给两个结论。

换检查方式要说明对原目标和阈值的等价覆盖；覆盖证明不了，受影响的结论保持待完成。

最小上下文用户检查：用没参与产出、测试或审查的新身份。只给用户任务、可见规则、普通启动或安装或帮助材料、真实入口、隔离的合成数据、环境限制和可识别的候选版本。不给源码、内部设计、开发者结论、测试用例、隐藏预期和成功路线。让它自己用真实 UI、CLI、API 或产物完成任务，再试错误和恢复，记录尝试、困惑、观察和可复现缺陷。首份报告之后由主代理映射验收。工具或环境影响做不了就记未验证，别用代理体验代替真人判断。

## 证据

| 字段 | 内容 |
| --- | --- |
| 验收对象 | 验收 ID、检查、角色身份、提供的输入 |
| 被测状态 | 设计和契约版本、候选标识、环境和数据 |
| 实际执行 | Run、Expected、Observed、产物或复现步骤 |
| 结果状态 | 通过、失败、未运行、过时、明确例外 |
| 剩余工作 | 没覆盖的行为、下一步 |

- 候选标识：commit 只标识干净且全部提交的被测树。脏工作区或非 Git 产物要用文件、相关未跟踪检查和产物指纹，或等价的可复现标识。
- 变更后在新候选上重跑受影响的证据。沿用未受影响的证据就说明依据。
- build 或 typecheck 只证明自己那块。最终检查要覆盖变化和没覆盖的跨系统路径。

## 完成判断

- 阻塞项关掉才能算完成；没关就报部分交付，说清缺什么。
- 缺口分类回流：产物缺陷回执行；需求歧义回 Interview；方法不适配或评价能力不足回调研。
- 纯设计：只检查覆盖、契约、来源和失败场景，运行验证保持待完成。
- 交付简报：原始要求、实际产物、被测 revision 或产物标识、跑过的检查和结果、剩余限制、最短使用或恢复步骤。
- 声明"通过""变好了""比原方法强"要分别举证。没做可比基线检查就别声称元规划带来了提升。
- 打开能跑的入口给用户用。打不开就如实说，别宣称成功。
