# 记录与恢复

保存已批准的事实、暂停、恢复或收尾时读。

- 按项目现有惯例记，只记有用的。轻量版通常一份任务说明；正式版用索引连接范围、契约、任务和证据。

## 记什么

- 阶段：模式、阶段、要交的东西。
- 批准依据：批准的范围和方案、用户实际确认过什么、明确的阶段例外。代理写的简报和推荐不算用户确认。
- 有效版本：需求、调研、设计、契约和审查各自的最新版本。
- 任务：任务、负责人、带类型的依赖、阻塞项。
- 证据：跑过的检查、被测候选版本、通过或失败或未运行或过时。
- 待定：未决选择、限制、下一步允许的动作。
- 需求简报：按 [interview.md](interview.md#需求简报) 记结果、范围、约束、验收、深度和待定项。
- 方案：体验、边界、替代方案、复用还是自建、义务、风险、委派细节、首次验证、交付范围。
- 决策：背景、选择、最强的替代方案（含维持现状）、排除理由、收益和成本、验证和重议条件。
- 能力诊断：3–5 行小结每次都要留。只有诊断改变决定时，才另外记缺口、原方法、新方法、决定性检查、受影响任务、实际结果和退出理由；并进现有任务或决策，不另开台账。
- 方法复用：留下查过的方法、适用条件、版本、失败边界和证据。没验证过的候选保持假设，下次用前先核对时效和适配。

## 放哪

没有既有约定时：

| 内容 | 位置 |
| --- | --- |
| 已实现概览、快速开始、导航 | README |
| 当前行为、架构、契约、用法 | docs/design 或专题文档 |
| 重要决策和替代方案 | docs/decisions |
| 带日期的一手调研和来源索引 | docs/research 或功能说明 |
| 提议改动、任务状态、交接 | 现有功能或任务记录 |
| 过时叙述、已完成的临时计划 | docs/history |

- 已接受的决策保留原路径，标出被替代的范围和理由。
- 正式文档只写已经实现的内容；待做的明确标成提议。
- 术语有实际用途才定义，一事一名。
- 收尾同步更新行为、契约、就绪状态、证据、决策和链接，保留一份当前状态表。

## 恢复与交付

- 先看实际文件和候选产物，再读检查点。重新派发前核实批准、契约版本和证据时效。
- 缺失或过时的证据堵住依赖它的任务；去获取证据的调研可以就绪。
- 交付简报按 [build.md](build.md#完成判断)，交接加：目标、做完的事、决策的唯一来源、检查、风险、下一步。
- 别塞秘密、无关对话、空模板和重复的历史目录。
- 本地做完不等于获得发布、部署或写外部任务系统的授权。
