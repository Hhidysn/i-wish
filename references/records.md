# Records and resume

Read when saving approved facts, pausing/resuming or closing an increment.
Use existing conventions; create useful records only. Lite usually needs one
feature/task note; full an index linking scope, contracts, tasks and evidence.

## State and templates

```text
Mode / current phase / requested delivery
Approved scope-solution + actual user confirmation or named stage exception
Canonical requirements / research / design-contract-audit versions
Tasks / owners / typed dependencies / blockers
Checks actually executed / tested candidate / passed-failed-not-run-stale
Unresolved choices / limits / next permitted action
```

Brief: outcome/audience; scope/non-goals; constraints/compatibility; acceptance/checks;
delivery/depth; defaults/unknowns. Recommendation: experience, boundaries, alternatives,
reuse/custom, obligations, risks, delegated details, first proof and delivery scope.
Do not confuse either agent-written artifact with user confirmation.

Decision: context, choice, strongest alternatives including keep-current,
rejection reasons, benefits/costs, validation and revisit conditions.
Evidence follows [verification.md](verification.md); link instead of duplicating.

## Locations

| Purpose | Default when no convention exists |
| --- | --- |
| Implemented overview, quick start, navigation | README |
| Current behavior, architecture, contracts, usage | docs/design or topic docs |
| Important decisions and alternatives | docs/decisions |
| Reusable dated primary-source findings | docs/research or feature note |
| Proposed changes, task/milestone state, handoff | Existing feature/task record |
| Superseded narratives, completed temporary plans | docs/history |

Keep accepted decisions at stable paths; mark superseded scope and replacement,
preserve rationale. Current docs describe implemented truth; pending details stay
explicitly proposed. Define shared vocabulary only when useful, one canonical term.

At increment/milestone close and delivery, reconcile changed behavior, contracts,
readiness, evidence, decisions and links. One current status table; review-round
history separately. Distinguish fixed findings from discovered unresolved work.
Counts and completion claims come from named rerunnable checks.

Resume: inspect actual files/candidate and checkpoint; validate approvals, contract
versions and evidence before redispatch. Missing/stale evidence blocks dependent
tasks requiring it; apply kind-specific readiness in [full.md](full.md). Research
to obtain or refresh that evidence may be ready.
Finish unaffected authorized work; ask only missing or changed material decisions.
Handoff: goal, completed work, canonical decisions, checks, risks, next action.
No secrets, irrelevant dialogue, empty templates or duplicate history trees.
Local completion does not add publication/deployment/external tracker authorization.
