## 已批准目标

用户确认：合并 `SKILL.md`、`lite.md`、`full.md`，入口只讲流程；计划与实现细节
分别进 `plan.md`、`build.md`；`agents.md` 表格与散文去重；调研开头强制做一次
能力缺口诊断（二阶搜索），需要时再做一次三阶策略调整；正文改成短句白话，
删掉冗余关键词。D1–D4 按推荐执行；调研阶段允许把候选下载到项目外临时目录
做分析和静态检查，跑代码仍走 Gate 2。两道门禁、独立质询与独立验收保持不变。

## 决定

1. **运行集 8 → 6**：`SKILL.md`、`interview.md`、`plan.md`、`build.md`、
   `agents.md`、`records.md`。删除 `lite.md`、`full.md`、`research.md`、
   `verification.md`；其行为并入按阶段读取的 `plan.md` 与 `build.md`。
   运行时正文 1617 → 956 词（脚本按空白分词，仅作体量对照）。
2. **入口只管流程**：选模式、两道门禁、沟通、推进与完成。角色与派发、
   调研细节、验证细节各有唯一归属，入口用链接指向。
3. **调研第一步强制能力诊断**：知识、方法、工具、评价四类缺口，每个实质缺口
   写明影响哪个已批准目标与哪项决定性检查；结论写 3–5 行。无缺口只记结论，
   不额外开二阶搜索。默认模型的知识会过时，版本、API、价格、平台规则不凭记忆。
4. **二阶搜索按缺口选方向**：渠道、工具、用法、方法、评价；采纳的方法要给出
   可执行步骤并落到设计要求、依赖或检查。三阶只对同一个决定性问题换一次策略，
   换名字不算换问题，到约定时间或成本边界即停。
5. **调研期动手边界**：项目外临时目录的下载、阅读与静态分析直接可做，不执行
   候选的代码、钩子或构建脚本；跑代码、装依赖、改变采纳决定的实验、有副作用
   或花钱的操作要 Gate 2 批准，批准只让实验就绪，消费者等结果。
6. **`agents.md` 角色表是唯一角色规范**：列为「拿到什么 / 交回什么」，散文只留
   派发规则。正文改中文，与其余参考一致。
7. **验收与检查同步**：`scripts/check.mjs` 预算改为入口 600、计划 550、
   产出与验证 450、角色 400、记录 350、interview 220；`evals/check.test.mjs`
   的 fixture 与行数断言改为 6；`evals/cases.md` 的 S03/S07 改用新文件名与上限。
8. **顶层 reference 必须有显式预算**：`references/` 直接层的 `.md` 缺预算条目即检查失败，
   深一层的嵌套参考仍用默认 700。这补上了 S07 一直写着、但 `?? 700` 从未实现的失败条件，
   并保住嵌套参考的指纹测试。
