Status: Accepted

fast demos, concise runtime instructions, deeper formal-project orchestration,

The owner confirmed scope and explicitly authorized research, final design and

## Decision

Keep root `i-wish` and its invocation; choose lite/full by scope and consequence.
Retain full/formal project mode across narrow tickets and verification unless the
user explicitly changes it; preserve the already-required independent controls.
Entry owns approval and change boundaries; mode guides own execution depth.
Role, research, verification and record contracts have one canonical source each.
Intake reads the entry; later phases load applicable references. Preserve optional
language examples and game guidance. Remove four superseded active references;
historical links point to the frozen snapshot.

Default intent/solution confirmations remain. Existing approval and explicit stage
skips persist. Internal module refinement and acceptance-blocking repairs proceed;
reconfirm only changed user-owned results or approved commitments.

Global coverage/shared obligations precede module details. Each module checks its
delta, relevant evidence, detail, independent audit and task readiness. Audit reuse
requires matching version, contracts, assumptions and coverage. Adoption-disqualifying
unknowns block dependent design as well as coding.

After solution approval, split tasks and milestone checks. Readiness is kind-specific;
a research task need not know its answer. Consumers can construct with an approved
versioned contract and executable stub/producer candidate; acceptance uses real
integration. Group cyclic integration work; do not require every predecessor fully
done before dependent construction.

Use distinct-model proposals for open ideas, bounded parallel research for real
independent questions, independent design challenge, post-code independent test
authorship, and a separate fresh UX identity. The tester freezes behavior-derived
cases before source exposure. Full separates requirements/standards review contexts;
lite may batch the test author's later review, retaining separate verdicts. Native
read-only authors return exact patches for primary application.

Evidence binds to actual candidate, environment, role/inputs and executed operations.
Changes invalidate affected evidence. Missing required capability stays pending;
self-review or a fingerprint is not an independent execution pass.

## Alternatives considered

- Separate self-contained lite/full skill packages: cheaper individual activation;
  rejected because they duplicate policy and installation surfaces and change the
  existing single invocation without demonstrated need.
- Keep the current flow: preserves established hardening; rejected because fixed
  intake loads and absent role/readiness contracts do not meet the requested split.
- Complete all module detail upfront: easy to review once; rejected because distant
  decisions are speculative. Keep shared obligations, defer replaceable internals.
- Mandatory pre-code independent test-author round: earlier independent cases;
  rejected as default overhead. Define acceptance early; author tests independently
  after coding before seeing implementation. Earlier tests remain optional.
- New framework runtime, hooks or fixed provider roster: deterministic enforcement;
  rejected because host dispatch and Markdown records suffice for this skill.

## Consequences and validation

Less initial/context loading; deeper formal coordination. Independent roles still
cost calls and time; conditional reads cannot prove runtime efficiency improvement.
A single package makes routing consistency important. Missing host isolation or
runtime tools prevents a complete independent-verification claim.

Static checker enforces metadata, per-file budgets, local link/heading targets and
runtime self-containment; emits fingerprints and comparable whitespace word counts.
Independent cases, checker tests and bounded fresh probes are separate evidence.
Results and unverified behavior: [validation record](../history/2026-10-09-mode-refactor-validation.md).
