# 当前流程

本仓库是一个可安装的技能包：`i-wish`。轻量/正式是工作流深度，
不是两个必须分别安装的技能，也没有新的编排运行时。
[入口](../../SKILL.md)是授权、顺序和重开规则的唯一来源。

| 契约 | 当前实现 |
| --- | --- |
| A1 兼容与分流 | 保留根目录和调用名；按风险选择 lite/full；正式项目跨模块/验证继承模式；首次澄清只需入口 |
| A2 轻量成本 | 短卡、一轮有界调研、一条完整体验、一份有用记录；不强制文档套装 |
| A3 强制门禁 | 轻量/正式/纯设计均须 Gate 1 明确确认并等待；实际联网调研完成后设计；Gate 2 明确批准方案及交付范围并等待后才可写文件/代码；例外仅限用户指定范围 |
| A4 创意 | 开放方向由不同模型独立提案，随后针对实际分歧讨论 |
| A5 研究 | 真实问题分工并行；主代理核查决定性一手来源 |
| A6 设计 | 冻结方案，独立对抗审计；按版本、契约、假设和覆盖范围复用审计 |
| A7 渐进细化 | 整体覆盖与共享义务先行；每模块首次实现前差异→研究→细节→审计→就绪 |
| A8 任务 | 方案后拆任务/依赖/角色/验证；研究、设计、编码、集成、验收有不同就绪条件 |
| A9 集成 | 可以依批准契约和桩开始构建；真实生产者集成后才能验收；循环依赖归入集成任务 |
| A10 阶段 | 预先定义可用结果、覆盖、真实集成场景、失败恢复、环境及出口条件 |
| A11 测试 | 编码后新独立作者；看实现前从需求冻结断言；只读作者给补丁，主代理保存运行 |
| A12 审查 | 正式版需求/规范分别新上下文；轻量版可合并调用但结论分开 |
| A13 用户体验 | 不参与开发/测试/审查的新身份，只拿普通用户材料；真实入口、隔离数据、独立探索 |
| A14 证据 | 关联实际候选和运行；受影响变更使证据失效；缺项不能冒充通过 |

职责分别由[模式](../../references/full.md)、[代理](../../references/agents.md)、
[验证](../../references/verification.md)、[记录](../../references/records.md)维护。
每阶段按需读取；历史文档不是活动指令。

## 模块是否重新确认需求

先比对批准范围。未改变用户结果、验收、费用、数据、兼容或关键承诺：
主协调者细化并推进，不重新采访。只有缺失/改变的用户决定才局部确认；
新的技术未知只重开受影响研究/设计，阻塞依赖它的任务，其他工作继续。
整体审计未覆盖的模块决策要独立审计；相同有效设计无需每票重复。
