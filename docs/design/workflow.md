# 当前流程

本仓库是一个可安装技能包：`i-wish`。轻量/正式是**同一入口内的深度分级**，
不是两个独立技能，也没有新增编排运行时。[入口](../../SKILL.md)是路由、授权、
顺序与重开规则的唯一来源；各 reference 按阶段读取。

## 阶段

```
0 路由 → 1 Shape ▶ Gate 1 → 2 调研(必做在线) → 3 设计+独立对抗审计
→ 4 ▶ Gate 2(方案+任务拆分+阶段验收目标) → 5 产出(full 走模块就绪循环)
→ 6 独立验收(独立作者 → 双轴审查 → 最小上下文用户检查) → 7 交付
```

只有两道停等门禁，没有第三道。任务拆分与阶段验收目标是 Gate 2 批准内容的一部分，
不是单独门禁。

## 行为契约

| 编号 | 必须成立 |
| --- | --- |
| A1 | 单包单入口；按愿望**规模与风险**分流 lite/full；愿望不必是代码 |
| A2 | full 触发与规模无关：公共或持久契约、真实账户、敏感数据、不可逆影响、持续运维、需多次会话；新项目不自动是 full，已批准 full 不因单张小票降档 |
| A3 | 两档与纯设计都强制 Gate 1 与 Gate 2，均须停等；真实联网调研在 Gate 1 之后、设计之前完成 |
| A4 | 明确跳过只作用于用户点名的阶段，记为例外，不得推广；沿用同范围实际批准 |
| A5 | 开放创意由不同模型独立提案；真实研究问题拆成多个有界只读子代理，可并行 |
| A6 | 设计冻结后由独立子代理对抗审计，输入去偏（只给冻结产物与契约，不给作者推理） |
| A7 | 模块首次开工或证据失效时走 差异→研究→细化→独立审计→放行；普通 ticket 不重开采访 |
| A8 | 模块内细化默认继承全局授权；仅当引入未批准的用户可见结果/成本/数据外发/不可逆影响时补确认 |
| A9 | Gate 2 前给出粗粒度依赖图与阶段验收目标；批准后只记录与细化已授权任务 |
| A10 | 产物形成后由独立于产出者的作者推导验收；只读作者给补丁，主代理机械保存并运行 |
| A11 | 正式版需求与规范结论分开；轻量版可同一独立审查者双结论 |
| A12 | 最小上下文用户在**真实入口**检查最终产物；不给代码、实现解释、既有测试或成功脚本 |
| A13 | 无子代理时主代理做一次对抗性检查，标 `non-independent`，独立验收保持 pending，只报部分交付 |
| A14 | 记录 `Run/Expected/Observed`；证据绑定候选与实际执行；受影响变更使证据失效 |
| A15 | 交付给任务总结简报，并打开可运行产品的入口界面；打不开就如实说明 |

## 结构与成本

运行时 9 项：`SKILL.md` 加 7 个 reference，另有非运行时的来源表在 `docs/research/`。
字数上限由 `scripts/check.mjs` 强制：入口 600、lite 420、plain-language 220，
其余沿用既有上限。改版后入口从 649 降到 599 词（常驻成本下降），
深度增量转移到按需加载的 `full.md` / `verification.md` / `agents.md`。

删除 `references/game-projects.md`：本技能不做按愿望类型的独立验收模板，
领域特化样本会与"任意愿望"的定位相冲突。

## 边界

本技能是指令约定，不是工具权限拦截器；宿主需提供真实派发、上下文隔离与权限。
缺少独立能力或运行证据时如实报告，不把自审当作独立通过。
模拟用户证据不代替事先约定的人工判断。
